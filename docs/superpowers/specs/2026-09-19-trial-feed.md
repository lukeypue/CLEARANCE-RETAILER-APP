# Dated shared feed for the 84414 phone trial

The user wants a downloadable Android app that automatically lists clearance candidates at the nearest 3–5 stores, across six retailers. The free ScrapingBee trial proved Walmart discovery and store localization, but not complete clearance stock. Other retailers have incomplete or failed local data. This version makes that evidence browsable and establishes a bounded refresh pipeline.

Use the existing task branch and Java Android architecture. Python standard-library collection runs outside the phone. Its only credential input is SCRAPINGBEE_API_KEY. Manually dispatched GitHub collection uses a repository secret and at most 30 credits per run for three stores, with a 100-credit reserve. No schedule is enabled during the free trial. A shared JSON file on the repository branch is the phone's HTTPS source, plus a dated bundled copy for offline first launch. Checking that file spends no scraper credits. Clearly state that automatic collection is not active until the secret is configured and collection is run.

Schema version 1: generated_at epoch milliseconds; zip 84414; sources for all six chains (retailer, status, detail); stores (id, retailer, name, address, distance); offers (id, retailer, store_id, product_id, title, category, price_cents, original_cents optional, pickup boolean, observed_at epoch milliseconds, scope store_pickup/online, URL). Walmart candidates must match the requested response store ID, seller Walmart.com, numeric price >0, out_of_stock=false and pickup=true. Deduplicate by store/item ID; keep variants distinct; never synthesize original prices, quantities, clearance dates, or markdown percentages. Category is a title-derived browsing aid, not a retailer classification. Home Depot online deals can be exported only from complete product cards with parsed current prices; no local stock claim. Other retailers show source status, not invented products.

Discover defaults to 84414 and lists products immediately, with retailer/store/category filters and refresh of the published feed. Another ZIP shows an explicit trial-coverage message; Stores still supports nationwide mapped discovery and 3/5 nearest selection. Offer cards show title, listed price, physical store or online-only label, checked time, and link. All store listings state that shelf price, clearance markdown, and shelf quantity are unverified. Feed older than 60 minutes is marked older; refresh never resets observation times. Source statuses explain failed or incomplete trials. Sample catalog stays separate.

Fail closed on wrong-store responses, invalid schema, unsafe links, malformed prices/times and challenge pages. Keep previous valid cached data when refresh fails. HTTPS only, size limits, background I/O, lifecycle-safe observers, refresh cooldown. API keys never enter repository files, workflow inputs, APK or logs.

Tests: Python collector rejection and budget behavior; Android parser/coverage/cache preservation instrumentation; emulator Discover→store/category filters→offline cached feed, existing map flow and sample isolation. Version 0.3.0-test; retain existing debug signing cache. Deliver only after GitHub build and emulator checks pass. Full live inventory and app-store release remain out of scope for this trial build.
